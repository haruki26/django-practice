# 開発環境ガイド

本ドキュメントでは、Wellness Foods 販売支援システムの開発で使用する主な技術および日常的に利用するコマンドを整理しています。新規メンバーのオンボーディングや運用時の参照資料としてご利用ください。

## 使用技術
- **バックエンド**: Python 3.13 と Django 4.2 を使用します。Django はアプリケーション全体の実装基盤であり、認証やフォーム、ORM などの標準機能を活用します。
- **フロントエンド**: HTML・CSS・Vanilla JavaScript を基本とします。CSS は必要に応じて BEM などの命名規則を採用し、JS では最低限の DOM 操作のみを実装します。
- **データベース**: MySQL 8.0 を使用します。docker-compose によりローカル環境で起動し、`psysdb` スキーマに対してマイグレーションを適用します。
- **ドキュメント**: MkDocs + Material テーマで公開します。Docs 配下の Markdown ファイルを単一の情報源として管理します。
- **開発補助ツール**: uv をパッケージマネージャー兼ランタイムとして利用し、Ruff (フォーマッタ・リンター) と Pyright (型チェッカー) を組み合わせます。

## 開発時に利用するコマンド
`pyproject.toml` の `[tool.taskipy.tasks]` セクションに定義されているタスクを uv 経由で実行します。

| コマンド | 説明 |
| --- | --- |
| `uv run task fmt` | Ruff の `check --fix` と `format` をまとめて実行し、コードスタイルと静的解析の両方を整えます。|
| `uv run task type` | Pyright による型チェックを実行し、型安全性を確認します。|
| `uv run task dev` | Django 開発サーバー (`manage.py runserver`) を起動します。|
| `uv run task manage -- <args>` | 任意の Django 管理コマンドを実行します。例: `uv run task manage -- migrate`。|

## コンテナおよびデータベース
- `docker-compose up -d` でアプリケーションと MySQL をまとめて起動できます。終了時は `docker-compose down` を使用してください。
- 初期データは `docker/mysql/init/psysdb.sql` でロードされます。必要に応じてマイグレーション後にカスタムデータを投入してください。

## ドキュメント更新の流れ
1. 仕様や画面の変更が発生したら、まず `docs/app` 配下の該当ドキュメントを更新します。
2. 開発関連の追加情報は本ファイルに追記し、他のメンバーが迷わないようにガイドラインを整備します。
3. 変更内容をレビュー後、MkDocs サイトをビルド・公開して関係者に共有します。

以上の内容を随時アップデートし、最新の開発手引きとして維持します。
